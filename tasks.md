# PaintShop — задачи для WEEEK

**Источник требований:** семейный чат, 4 ноября 2026 года (включая четыре изображения-примера).
**Исходный код для сверки:** `savinshin/paintshop`, `main`, HEAD `7fc7951272404630e79a86607896b580213a6647`.
**Статус:** проект плана; задачи ещё не созданы в WEEEK, сроки не назначены.

## Правила разделения ответственности

- **Разработчик:** БД, миграции, рабочие сидеры, backend/API, Angular TypeScript, маршрутизация, функциональные шаблоны в существующем стиле, интеграция и проверки.
- **Дизайнер:** HTML/CSS финального представления, адаптивность и визуальная доступность, фотографии, иконки, логотипы, баннеры. Без самостоятельных изменений бизнес-логики, API или схемы БД.
- **Родители:** утверждение бизнес-требований, текстов, категорий, перечня брендов, достоверных контактов.
- **Правило завершения:** разработчик отмечает свою задачу после публикации изменений и фактической проверки; дизайнер начинает зависимые задачи после публикации соответствующей функциональности.
- **Без отдельного требования:** корзина, оформление заказов, оплата, избранное и личный кабинет покупателей не входят в объём работ, даже если встречаются на сайтах-референсах.

## Задачи разработчика

### P00 — Утвердить информационную архитектуру и исходные бизнес-данные
**Ответственный:** разработчик. **Приоритет:** высокий. **Зависимости:** нет.

Определить страницы и навигацию: «О нас», «Автозапчасти», «Материалы», «Подбор красок», «Автосервис», отдельная главная страница с баннерами. Согласовать URL, нужно ли сохранять общий `/catalog`, отображение контактных ссылок и расположение блока брендов. Запросить у родителей подтверждённые бренды, телефоны и мессенджеры. Не подставлять данные с референсов.

**Приёмка:** согласованная карта страниц и набор подтверждённых бизнес-данных. Решения переданы дизайнеру.

### D01 — Привести каталог категорий к разделам «Автозапчасти» и «Материалы»
**Ответственный:** разработчик. **Приоритет:** высокий. **Зависимость:** P00.

Проанализировать текущие `Category`, `ProductCategory`, миграции, API и `CategorySeeder`. Согласовать, достаточно ли существующей иерархии категорий или необходима корректировка схемы. Обновить `CategorySeeder.cs`, сохранив актуальные группы материалов и добавив десять групп автозапчастей: фильтры масляные; тормозные жидкости; щётки стеклоочистителя; моторные масла; антифризы; свечи автомобильные; тормозные диски; стеклоомыватели; автолампы; тормозные колодки дисковые. Фразу «Запчасти для легковых и грузовых российских авто» использовать как описание раздела, если родители не подтвердят, что это самостоятельная категория.

Согласовать последствия для `DemoProductSeeder.cs` и формы привязки товара к категориям. Без отдельного разрешения не сбрасывать БД и не применять миграции/сидеры.

**Приёмка:** структура позволяет отнести товар к корректному разделу; рабочий сидер воспроизводит согласованные категории; демо-сидер остаётся тестовым и не используется на production; целостность связей и повторный запуск сидера продуманы.

### D02 — Разделить публичный каталог на автозапчасти и материалы
**Ответственный:** разработчик. **Приоритет:** высокий. **Зависимости:** P00, D01.

Использовать существующие API и Angular-каталог, где возможно. Реализовать страницы/режимы для двух согласованных разделов с фильтрацией по иерархии категорий и поиском внутри выбранного раздела. Корректно обрабатывать отсутствие товаров, загрузку и ошибки. Сохранить существующие административные сценарии создания/редактирования товаров и авторизацию. Не придумывать URL до P00.

**Приёмка:** разделы не смешивают товары, поиск работает, категории отображаются, ссылки открывают правильный раздел, существующие административные операции не сломаны.

### D03 — Подготовить данные для блока популярных брендов
**Ответственный:** разработчик. **Приоритет:** средний. **Зависимости:** P00, D02, предоставление списка брендов родителями.

Текущий `Product.Brand` — строка. Определить, нужен ли отдельный справочник брендов: если блок является фиксированной витриной логотипов, не создавать таблицу без необходимости; если бренды нужно управлять через админку или показывать до появления товаров, согласовать устойчивую модель. Подготовить данные/контракт для визуального блока. Не считать логотипы с чужого сайта утверждённым списком.

**Приёмка:** отображаются только утверждённые бренды; данные передаются дизайнеру без хардкода неподтверждённых значений; решение по необходимости новой таблицы обосновано.

### D04 — Создать самостоятельную страницу «О нас»
**Ответственный:** разработчик. **Приоритет:** высокий. **Зависимость:** P00.

Создать отдельный маршрут и компонент Angular; перенести в страницу утверждённый текст, который отец прислал 4 ноября 2026 года, без самовольной правки фактов. Добавить заголовок/SEO, функциональные навигационные ссылки и минимальную разметку в текущем стиле. Главная страница должна остаться самостоятельной.

**Приёмка:** «О нас» открывает правильный маршрут; текст полный; прямое открытие URL работает; нет сломанных ссылок.

### D05 — Реализовать страницу «Автосервис» с перечнем услуг
**Ответственный:** разработчик. **Приоритет:** высокий. **Зависимость:** P00.

Исправить содержание текущего `/body-repair` (сейчас на нём контакты, а не услуги), сохранив существующий URL или изменив его по решению P00. Разместить семь подтверждённых услуг: кузовной ремонт после ДТП; покраска автомобиля целиком; покраска бампера; покраска отдельного элемента; покраска авто в камере; ремонт порогов. Исходное сообщение содержит именно шесть конкретных услуг — не добавлять седьмую без подтверждения. Сохранить корректные переходы, SEO и минимальную функциональную разметку. Контакты не потерять — определить им подходящее место.

**Приёмка:** посетитель видит согласованный список услуг; содержание соответствует разделу; контакты доступны по подтверждённым ссылкам; нет выдуманных услуг.

Тексты из чата: «Профессиональная колеровочная система», «Подбор автоэмалей», «Профессиональные материалы для кузовного ремонта», «Услуги автосервиса — профессиональная работа мастеров кузовного ремонта», «Широкий выбор автозапчастей». Подготовить места для отдельных изображений и визуальных настроек дизайнера. Не копировать сторонние рекламные предложения о доставке и покупке.

**Приёмка:** все пять слайдов доступны, стрелки работают, нет ошибок Angular; графические ресурсы можно менять независимо от логики; без визуального редизайна в задаче разработчика.

### D07 — Согласовать функциональную навигацию и контакты
**Ответственный:** разработчик. **Приоритет:** высокий. **Зависимости:** P00, D02, D04, D05.

Проверить ссылки шапки, мобильного меню, главной и футера: «О нас», «Автозапчасти», «Материалы», «Подбор красок», «Автосервис». Обеспечить доступность маршрутов и корректное закрытие мобильного меню. Для телефона и мессенджеров использовать только подтверждённые контакты; согласовать с дизайнером, кто подставляет контент в HTML.

**Приёмка:** меню не содержит ссылок на несуществующие страницы, мобильная навигация работает, данные контактов не придуманы.
